# Stadium Performance Model

Monthly contract performance assessment for the Tātaki Auckland Unlimited stadiums maintenance contract (Go Media Stadium Mt Smart), built on the Schedule 1 Performance Model, the Performance Model Calculation Sheet Draft V4 (21 November 2026) and the Stadiums Maintenance Technical Specification (21 November 2026). FieldTurf NZ is the sample contractor.

## What it does

- **Dashboard**: for the month chosen in the top bar, the overall score, fee paid, abatement, rectification plan test, year to date score and incentive progress; charts of the overall score and fee by month; KPI results for the month; KPI results by month (heat map); event failures and deductions for the month; Part F escalation tests; fee and band totals; Save as PDF (landscape A4 monthly report).
- **Events**: the event calendar and the joint readiness sign-off scorecard for each event. Every event-scored standard is marked Pass or Fail with an observation. Each KPI's event score updates as you go. KPI-V is only scored at the first event after renovation.
- **Monthly**: the deduction log for the month (incidents, audit breaches, late or incomplete items, monthly measured standards), confirmed by the Principal's Representative, and Part F relief (not assessed) for any KPI.
- **Bands**: the annual band reconciliation (Part E) for every band in the specification.
- **Model**: the 13 scored KPIs with base and monthly weightings (core sports turf 85%, KPI-GD Gardens 10%, KPI-HS Hard Surfaces 5%; KPI-U Usage Cameras is report only), scoring categories, score to fee table, escalation ladder and the full register of 169 performance standards with their targets and measurement methods.
- **Setup**: contractor name, contract year, last month reported, condition trends, all fee and scoring settings, KPI base weightings and the monthly weightings grid, export to Excel, backup and restore (JSON), sample data.

Results are kept in the browser only and are not uploaded to Netlify. Use Export backup and Import backup to move them between people or computers.

## Scoring rules (same as the Calculation Sheet V4)

- Event score: each KPI with event-scored standards starts at 100 at every event and loses 20 points per failed standard (floor of zero).
- KPI result for a month: mean of the month's event scores (100 with no event) less confirmed deductions, capped at 30 points per standard. Category points: B breach (incident, audit or monthly measured) 10, D late or incomplete 5, G report only 0. KPI-U Usage Cameras standards are report only (U1.7 and U1.9 remain critical).
- Monthly weightings: each KPI's weight varies by month (Monthly Weights sheet), so seasonal work counts when it happens: KPI-V 7.5% in November and February only; KPI-GD 10% in August, November, February and May (3% otherwise); KPI-HS 5% in September, November, January, March and May (2% otherwise). The other core turf KPIs share the rest of each month in proportion to their base weights. A KPI at 0% in a month shows as Not scored this month.
- Overall score: weighted sum of KPI results using that month's weights, divided by the weights of the KPIs assessed (relief reallocates a KPI's weight).
- Fee: 90 or above pays 100%; below 90 the fee reduces 1% per full point, capped at 15%.
- Rectification plan: any event failure, any critical standard failure, or two consecutive months below 90.
- Escalation: three months below 90 in any rolling six; six in any twelve. Incentive: nine months at 95 or above with improving condition trends.
- Months after the last month reported are left blank.

## Deploy to Netlify via GitHub

1. Create a private GitHub repository (for example `stadium-performance-model`) and upload the contents of this folder to it (Add file > Upload files, drag everything in, Commit). Leave out `build_model.py`, `make_ts.py` and `ts.json` if you prefer; the site does not need them.
2. In Netlify: Add new site > Import an existing project > GitHub, choose the repository. No build settings are needed (`netlify.toml` publishes the folder as is).
3. Site configuration > Environment variables, add `SITE_PASSWORD` (any username works). Set this before sharing the URL.
4. Deploys > Trigger deploy so the variable takes effect. Later changes pushed to GitHub deploy automatically.

## Updating the model

`js/model.js` is generated by `build_model.py` from the Calculation Sheet V4 (Inputs, Monthly Weights, Standards Register, Band Reconciliation) and the Technical Specification standards tables (`ts.json`, made by `make_ts.py` from the specification Word file). Change the workbook or specification, then regenerate:

    python make_ts.py "Auckland Council Stadiums - Technical Specification 21.11.2026.docx" ts.json
    python build_model.py "Performance Model Calculation Sheet - Draft V4 21.11.2026.xlsx" ts.json js/model.js

The build finds the KPI, month and band rows by their labels, so KPIs can be added on the Inputs sheet without editing the script.

Base and monthly weightings, thresholds and points can also be changed in Setup without regenerating. When the model version changes, any weightings saved in a browser are reset once to the new model weightings (a notice explains this); events, deductions and bands are kept.

## Files

- `index.html` app shell
- `css/app.css` styles (same system as the Enhanced Pruning Performance app, in TAU teal)
- `js/model.js` the performance model (KPIs, weightings, standards, categories, bands)
- `js/core.js` scoring rules (no DOM)
- `js/sample.js` illustrative FieldTurf NZ data, July to October 2026 (includes one Gardens deduction and one Hard Surfaces event failure)
- `js/app.js` user interface
- `netlify.toml` password gate and headers
- `netlify/edge-functions/auth.js`
